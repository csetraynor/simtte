# simtte: Simulate Time-to-Event Data from PK/PD and Bespoke ODE Models

## Details

Simulates time-to-event (survival) datasets for clinical trial design
and analysis, including datasets driven by a joint
pharmacokinetic/pharmacodynamic (PK/PD) model solved via the mrgsolve
backend.

## Which functions go together

The usual chains:
[`tte_model`](https://csetraynor.github.io/simtte/reference/tte_model.md)
(or a name from
[`sim_tte_ode_models`](https://csetraynor.github.io/simtte/reference/sim_tte_ode_models.md))
\\\to\\
[`sim_tte_ode`](https://csetraynor.github.io/simtte/reference/sim_tte_ode.md)
\\\to\\
[`add_censoring`](https://csetraynor.github.io/simtte/reference/add_censoring.md)
and/or
[`add_interval_censoring`](https://csetraynor.github.io/simtte/reference/add_interval_censoring.md).
For visit schedules:
[`visit_schedule`](https://csetraynor.github.io/simtte/reference/visit_schedule.md)
\\\to\\
[`thin_visits`](https://csetraynor.github.io/simtte/reference/thin_visits.md)
or
[`visit_schedule_informative`](https://csetraynor.github.io/simtte/reference/visit_schedule_informative.md)
\\\to\\
[`add_interval_censoring`](https://csetraynor.github.io/simtte/reference/add_interval_censoring.md).
For the older closed-form path:
[`sim_tte`](https://csetraynor.github.io/simtte/reference/sim_tte.md) or
[`sim_tte_df`](https://csetraynor.github.io/simtte/reference/sim_tte_df.md),
with
[`explore_pi_tq_surv`](https://csetraynor.github.io/simtte/reference/explore_pi_tq_surv.md)
for exploration. In parallel or multi-process runs,
[`simtte_prepare_model`](https://csetraynor.github.io/simtte/reference/simtte_prepare_model.md)
wraps the model step on each worker.

## Joint PK/PD and time-to-event simulation

[`sim_tte_ode`](https://csetraynor.github.io/simtte/reference/sim_tte_ode.md)
locates each subject's event time directly during ODE integration
("in-solver" event detection): the survival probability is added to a
PK/PD model as one more ODE compartment, `p11`, with
`dxdt_p11 = -p11 * HAZ`, and the solver is watched for the first
internal evaluation at which `p11` falls to or below a per-subject
uniform draw. Six built-in library models (`"pk_hazard"`,
`"irm1_hazard"`–`"irm4_hazard"`, `"tmdd_hazard"`;
[`sim_tte_ode_models`](https://csetraynor.github.io/simtte/reference/sim_tte_ode_models.md)
lists all of them) cover common PK/PD structures out of the box. See
[`vignette("pkpd-time-to-event", package = "simtte")`](https://csetraynor.github.io/simtte/articles/pkpd-time-to-event.md)
for a full walkthrough.

## Bring your own PK/PD model

[`tte_model`](https://csetraynor.github.io/simtte/reference/tte_model.md)
converts any user-supplied mrgsolve model (one with an `$ODE`/`$DES`
block) into one usable by
[`sim_tte_ode`](https://csetraynor.github.io/simtte/reference/sim_tte_ode.md)
the same way as a built-in model, including coexistence with a model's
own declared `$OMEGA` block. See
[`vignette("bring-your-own-model", package = "simtte")`](https://csetraynor.github.io/simtte/articles/bring-your-own-model.md).

## Covariates, the linear predictor, and between-subject variability

[`sim_tte_ode`](https://csetraynor.github.io/simtte/reference/sim_tte_ode.md)'s
`covariates`/`beta` (optionally `formula`, built into a design matrix
via [`model.matrix`](https://rdrr.io/r/stats/model.matrix.html)) add a
linear predictor `lp(t) = X(t) %*% beta` to any model; `omega` adds
log-normal between-subject variability on a model's own structural PK/PD
parameters. See
[`vignette("pkpd-time-to-event", package = "simtte")`](https://csetraynor.github.io/simtte/articles/pkpd-time-to-event.md).

## Bespoke parametric/flexible hazard simulation

[`sim_tte`](https://csetraynor.github.io/simtte/reference/sim_tte.md)/[`sim_tte_df`](https://csetraynor.github.io/simtte/reference/sim_tte_df.md)
are the original API: a unified interface for closed-form Weibull and
flexible M-spline baseline hazards, plus a fully model-agnostic entry
point
([`sim_tte_df()`](https://csetraynor.github.io/simtte/reference/sim_tte_df.md))
for any already-simulated `(ID, time, p11)` trajectory from any source.
Event times are generated by inverse transform sampling from the
resulting cumulative hazard function (Bender et al. 2005), with an
optional sub-grid refinement (`event_time_method = "log_survival"`). See
[`vignette("introduction", package = "simtte")`](https://csetraynor.github.io/simtte/articles/introduction.md).

## Right censoring

[`add_censoring`](https://csetraynor.github.io/simtte/reference/add_censoring.md)
adds a second, independent censoring process to the output of any of the
three simulation functions above: a per-subject censoring time drawn
from an exponential, Weibull, uniform, lognormal, gamma, or
user-supplied distribution, with the observed time becoming
`min(event time, censoring time, administrative end)`.
[`censoring_rate_for`](https://csetraynor.github.io/simtte/reference/censoring_rate_for.md)
solves for the distribution parameter giving a target censoring
fraction;
[`draw_censoring_times`](https://csetraynor.github.io/simtte/reference/draw_censoring_times.md)
draws from the same kind of spec directly.
[`sim_tte_ode`](https://csetraynor.github.io/simtte/reference/sim_tte_ode.md)
also accepts a `censoring` argument that applies this automatically,
inside its own seeded draw. See
[`vignette("censoring-and-assessment", package = "simtte")`](https://csetraynor.github.io/simtte/articles/censoring-and-assessment.md).

## Interval censoring and visit schedules

[`add_interval_censoring`](https://csetraynor.github.io/simtte/reference/add_interval_censoring.md)
maps an already-simulated (and, if applicable, already right-censored)
outcome onto an interval `(L, R]`, given a visit/assessment-time
schedule –
[`visit_schedule`](https://csetraynor.github.io/simtte/reference/visit_schedule.md)
builds one with fixed spacing and optional per-subject jitter,
[`thin_visits`](https://csetraynor.github.io/simtte/reference/thin_visits.md)
layers non-informative missed visits/dropout on top, and
[`visit_schedule_informative`](https://csetraynor.github.io/simtte/reference/visit_schedule_informative.md)
layers a visit process that reacts to the simulated outcome.
[`sim_tte_ode`](https://csetraynor.github.io/simtte/reference/sim_tte_ode.md)
also accepts a `visits` argument that applies interval censoring
automatically, always after any `censoring`. See
[`vignette("censoring-and-assessment", package = "simtte")`](https://csetraynor.github.io/simtte/articles/censoring-and-assessment.md).

## Full mrgsolve import

Not narrowed to `importFrom()`: mrgsolve defines several of its own
methods on base generics (`as.data.frame`, `as.matrix`, ...) via S4
`setMethod()`/`exportMethods()`, not plain S3 registration (confirmed
directly: `mrgsims` is an S4 class, and `as.data.frame.mrgsims` is not
found by [`.S3methods()`](https://rdrr.io/r/utils/methods.html) even
once mrgsolve's namespace is loaded). Narrowing this to
`importFrom(mrgsolve, mread, mrgsim, ...)` was tried and broke
`as.data.frame(mrgsim(...))` dispatch under `devtools::load_all()`
(`.sim_surv_df()`'s own `as.data.frame(out)` call, used by every
[`sim_tte()`](https://csetraynor.github.io/simtte/reference/sim_tte.md)/
[`sim_tte_df()`](https://csetraynor.github.io/simtte/reference/sim_tte_df.md)
call) – a full `import()` is what makes a dependency's S4 methods on
base generics reliably dispatchable from the importing package's own
code, not just its exported function names, so it is kept.
